# 힙 정렬 AI 학습 자료

작성일: 2026-09-30. 작성 도구: OpenAI Codex.
이 문서는 AI가 제공하는 학습용 설명이며 학생과 AI가 실제로 주고받은 문답의 원문 기록이 아닙니다.

## 1. 힙 정렬은 무엇인가?

최대 힙을 만든 뒤 루트의 최댓값을 배열 맨 뒤로 보내는 작업을 반복하는 비교 정렬이다.
최대 힙은 부모 키가 자식 키 이상이라는 조건을 갖는 완전 이진 트리다.
배열 인덱스가 0부터 시작하면 i의 자식은 2i+1과 2i+2이다.
힙은 전체가 정렬된 배열이 아니며 형제 사이에는 대소 관계가 필요 없다.

## 2. 왜 큰 자식과 교환하는가?

부모가 두 자식보다 작을 때 작은 자식과 교환하면 큰 자식이 여전히 부모보다 커진다.
큰 자식과 교환해야 현재 위치의 힙 조건이 회복된다. 내려간 원소에 대해서 반복하면 된다.

## 3. 어떻게 동작하는가?

[4,1,3,2] → 힙 구성 [4,2,3,1]
→ 최댓값 4 확정 [3,2,1 | 4]
→ 3 확정 [2,1 | 3,4]
→ 2 확정 [1 | 2,3,4]
세로선 오른쪽은 정렬이 끝난 영역이다. 매 단계 루트를 맨 끝과 교환한 뒤
힙의 크기를 하나 줄이고 siftDown을 수행한다.

## 4. 힙 생성이 왜 O(n)인가?

높이 h인 노드 수는 대략 n/2^(h+1)개이고, 그 노드를 내리는 데 O(h)가 걸린다.
총비용은 n × Σ(h/2^(h+1))의 상수배 이내다. 급수가 수렴하므로 O(n)이다.
모든 노드가 루트처럼 log n만큼 내려가는 것은 아니다.

## 5. 전체 시간과 공간은?

힙 생성 O(n), 최대 n-1회 추출마다 O(log n)이므로 최악 O(n log n)이다.
본 구현은 반복문으로 내려가므로 추가 공간은 O(1)이다.
중복이 허용되고 모든 값이 같으면 siftDown이 즉시 멈춰 전체가 O(n)일 수 있다.
따라서 '어떤 입력에서도 정확히 n log n'이라고 말하면 부정확하다.

## 6. 안정 정렬인가?

아니다. [2A,2B,1C]를 본 코드로 정렬하면 [1C,2B,2A]가 되어 같은 키 2의 순서가 뒤집힌다.
태그는 결과 검사에만 쓰고 정렬 비교에는 쓰지 않는다. 태그까지 정렬 키에 넣으면
원래 알고리즘의 안정성을 검사하는 실험이 아니다.

## 7. 병합 정렬과 비교하면?

둘 다 최악 O(n log n)이다. 본 병합 구현은 보조 배열 O(n)과 재귀 스택 O(log n)을 사용하며
동점에서 왼쪽 원소를 먼저 골라 안정적이다. 힙 정렬은 추가 공간 O(1)이지만 불안정하다.
동일한 시간 복잡도가 같은 실행 시간을 뜻하지는 않는다. 비교 횟수, 이동 횟수, 함수 호출,
메모리 접근 방식과 언어 실행 비용이 실제 시간을 바꾼다.
